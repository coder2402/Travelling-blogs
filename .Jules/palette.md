## 2024-05-14 - Application uses unconfirmed GET requests for destructive actions
**Learning:** This application executes destructive operations (like deleting reviews) using direct GET request links (`<a href="/delete-review/?id=...">`). This makes it exceptionally easy for users to accidentally delete data by misclicking, or for automated crawlers to inadvertently trigger deletions. Adding a native JS `confirm()` dialogue intercepts the navigation, requiring explicit user intent and significantly reducing the risk of accidental data loss, whilst maintaining the existing GET architecture constraint.
**Action:** When finding destructive actions triggered by simple links or immediate buttons, ensure an explicit confirmation step (like `confirm()` or a dedicated modal) exists. Additionally, prioritize converting these actions to POST/DELETE requests if backend modifications are permissible.
## 2026-03-06 - Broken Click Targets in Div-wrapped Buttons
**Learning:** When styling pseudo-buttons using a wrapper `div` around an anchor tag (`<a>`), placing padding on the `div` and leaving icons outside the `<a>` tag severely degrades the user experience by violating Fitts's Law. Users expect the entire visual "button" to be clickable, but only the text acts as a valid click target. Clicking the padding or the icon results in a frustrating "dead click."
**Action:** Always ensure that anchor tags inside button-like wrappers are set to `display: block` (or inline-block) and that all clickable padding is applied to the `<a>` element itself, not the wrapper. Furthermore, ensure all visual components of the button (like icons) are nested *inside* the `<a>` tag so they are part of the clickable area.
## 2024-05-24 - Accessibility issues with heading tags for visual styling
**Learning:** Using heading tags like `<h1>` to achieve specific visual styling (like bold text or larger font size) for non-heading text, such as list items or usernames within repeated UI cards, severely disrupts the document outline for screen reader users. Screen readers use heading tags to navigate the page structure, and misusing them makes the content confusing and hard to traverse.
**Action:** Always use appropriate semantic elements (like `<p>` or `<div>`) for text that is not a true section heading. Apply the desired visual styling using CSS classes instead of relying on default browser styling for structural elements.
## 2024-11-20 - Fitts's Law and Boundary Styles in Pseudo-buttons
**Learning:** Applying visual boundary styles (like `border`, `border-radius`, and `background-color`) to a wrapper `div` instead of the inner anchor (`<a>`) tag creates deceptive interactive elements. Even if the anchor has `display: block` and some padding, clicking the border or background of the wrapper results in dead clicks. The visual boundary of the button must match the interactive hit area perfectly.
**Action:** When styling pseudo-buttons, always apply boundary-defining CSS properties directly to the `<a>` element, ensuring it acts as the full interactive surface area of the component.
